# RACObjC on GNUstep

RACObjC builds as a shared library (`libRACObjC.so`) on GNUstep, for example
on FreeBSD (including Gershwin) or Linux. Apple platforms are unaffected: they
keep using CocoaPods/Xcode, and every source change is behind `#ifdef GNUSTEP`
or a guard that is already true on Apple (`OS_OBJECT_USE_OBJC`,
`#ifndef NS_ERROR_ENUM`).

## Requirements

- clang
- libobjc2 (the `ng` runtime: `-fobjc-runtime=gnustep-2.x`)
- gnustep-make, gnustep-base
- libdispatch (swift-corelibs-libdispatch)
- gnustep-base built **with libdispatch run loop integration**, so that
  `RACScheduler.mainThreadScheduler` (the main dispatch queue) is drained by
  `NSRunLoop`. Check with:

  ```sh
  grep GS_USE_LIBDISPATCH_RUNLOOP $(gnustep-config --variable=GNUSTEP_SYSTEM_HEADERS)/GNUstepBase/GSConfig.h
  ```

  It should print `1`. Gershwin's build (gershwin-developer) builds libdispatch
  before gnustep-base, so this works out of the box.

Supported CPUs: aarch64 and x86_64 (see *rac_signalForSelector:* below).

## Build, test, install

From `Core/RACObjC`, after sourcing `GNUstep.sh` (on FreeBSD use `gmake`):

```sh
gmake                 # obj/libRACObjC.so
gmake check           # build and run GNUstep/Tests/RACSmokeTests
GNUSTEP_INSTALLATION_DOMAIN=USER gmake install   # into ~/GNUstep
```

## Using it

```objc
#import <RACObjC/RACObjC.h>
```

```make
# in your GNUmakefile
MyApp_GUI_LIBS = -lRACObjC -ldispatch
ADDITIONAL_OBJCFLAGS += -fobjc-arc -fblocks
```

## What is different on GNUstep

| Area | Apple | GNUstep |
|---|---|---|
| `rac_signalForSelector:` | installs `_objc_msgForward` | installs `RACObjCMsgForward` (see below) |
| Super calls in swizzled `-dealloc` / `-methodSignatureForSelector:` | `objc_msgSendSuper` | `objc_msg_lookup_super` |
| CoreFoundation (`CFArray`, `CFBinaryHeap`, `CFBridging*`) | system CF | small hidden Foundation-based shims (`RACCFShims.m`) |
| DTrace probes (`*.d`) | generated by Xcode | no-op headers (`shim/`) |
| libdispatch objects | ObjC objects (ARC) | C objects; retained/released by hand |
| `+[NSData rac_readContentsOfURL:options:scheduler:]` | uses `options` | `options` ignored (no `NSDataReadingOptions`) |
| `+[NSURLConnection rac_sendAsynchronousRequest:]` | `sendAsynchronousRequest:` | synchronous request on a private `NSOperationQueue` |

### rac_signalForSelector:

libobjc2 has no `_objc_msgForward`. Instead, gnustep-base hands out a
forwarding IMP per call (via the `__objc_msg_forward2` hook), and that IMP is a
temporary libffi closure that dies with the current autorelease pool, so it
cannot be stored in a method table. `GNUstep/RACObjCMsgForward.c` provides a
permanent IMP that saves the argument registers, asks the hook for the
forwarding IMP, restores the registers and tail-calls it, which is what the
runtime itself does for an unknown selector. It is written for aarch64 and
x86_64. Struct, union and vector return types are rejected, the same as on Apple.

### Workarounds for gnustep-base bugs

Both are still present in gnustep-base master (checked 2026-11-02):

- `NSDate` small-object (tagged) dates cannot represent an interval of exactly
  `0.0` (it reads back as `2.0`). `RACTestScheduler` therefore numbers directly
  scheduled blocks from 1 instead of 0.
- `-enumerateSubstringsInRange:options:` with
  `NSStringEnumerationByComposedCharacterSequences` runs past the end of the
  range and throws `NSRangeException`. `RACStringSequence -array` walks the
  composed character sequences by hand.

## Files

```
Core/RACObjC/GNUmakefile          gnustep-make build
Core/RACObjC/GNUstep/
  RACGNUstepPrefix.h              force-included: CF subset declarations
  RACCFShims.m                    CF subset implemented on Foundation (hidden)
  RACObjCMsgForward.c             forwarding trampoline (aarch64, x86_64)
  RACObjCVersion.m                RACObjCVersionNumber / String
  shim/                           <pthread/pthread.h>, DTrace provider stubs
  Tests/                          RACSmokeTests (gmake check)
```

The original test suite (Quick/Nimble) is Apple-only; `RACSmokeTests` covers
signals, subjects, sequences, disposables, schedulers (including the main
queue), KVO, `RAC()`/`RACChannelTo`, `rac_signalForSelector:` (integer, double,
object and stack arguments, undefined selectors, protocols), dealloc
swizzling, `RACCommand` and the Foundation categories.
